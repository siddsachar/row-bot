How Row-Bot Keeps An Agent In Bounds

An assistant that reads your email, browses for you and runs commands is useful because it can act. This page tells, in one place, how Row-Bot keeps those actions in bounds: what it may do on its own, what waits for you, what it never does, and where the limits of that design are. For what stays on your computer and every connection Row-Bot makes, read Privacy And Safety.

In Short​

  • Actions go through your approval level. Sending, deleting, paying, most commands and anything outside the workspace wait for you, or for Auto's reviewer, unless you chose Hands-off.
  • Auto's reviewer reads only your words. It never sees web pages, files, email or tool results, so text an action picked up can't talk it into approving.
  • Outside text is marked as outside. Web pages, files, mail and app results reach the model fenced off, with an instruction not to follow what's inside.
  • Row-Bot's own data folder is off limits to its tools. Your conversations, settings and keys live there.
  • Only you can approve. Programs on this computer, including the ones Row-Bot runs, can look but can't approve, change settings or pair a device.

What Counts As An Action​

Most reading and searching just runs. An action that changes something, sends something or reaches outside goes through the approval gate:

  • reading or writing outside the workspace folder, and moving or deleting files anywhere;
  • commands that aren't on the read-only list, installs, background processes and servers;
  • paying, buying, booking, sending, posting, deleting, uploading and account changes in Row-Bot's browser, and paying, sending, deleting or changing settings in an app on your screen;
  • opening an address on this computer or your network in Row-Bot's browser;
  • looking at your screen or through your camera;
  • actions of apps, MCP servers included, and of packages, by what they do (read, change, send) and the access you gave the app in Settings › Apps. Deleting, sending, paying, publishing, running code and unknown actions go through the gate whichever access you chose;
  • messages and files sent through a channel;
  • creating, changing, moving and deleting calendar events, in Google Calendar and Outlook. Under Auto, an event that invites guests or emails them a change always asks you;
  • pictures and videos made with a model that charges for each one (an API key, or a paid OpenRouter model). The card says roughly what it costs, such as About $0.05, from the provider's own model list or its published list price (in US dollars, with the date Row-Bot last checked it), or Price unknown when Row-Bot has no price for that model. Your bill may differ: set a spending limit with the provider too. Pictures your plan includes, free models and models on this computer don't ask;
  • settings Row-Bot would change. Under Auto, turning on Shell, file tools, Browser, Computer use or MCP apps always asks you.

An action the gate doesn't recognise asks you. So does a stored approval level Row-Bot can't read: it counts as Ask. Tools, Approvals And Background Work covers every case.

The Four Levels​

You choose the level for each conversation with the composer's Approvals control. It decides what happens to an action that needs approval.

LevelWhat happensWorth knowing
AskYou approve each one on its card.Allow in this chat lets later actions of the same kind run; sending, deleting and paying still ask each time.
Auto (the default)The reviewer approves what clearly matches your request and asks you about the rest.Without a working model, everything asks you.
Hands-offEvery action runs without asking, and each one is recorded.Only you turn it on, in the app. A conversation other people share runs on Auto at most.
BlockAnything that would change something is refused.Reading still runs.

Nothing switches Hands-off on for you. Updates never move a conversation to it, Row-Bot's own tools can't set it, and a channel command can't turn it on. A conversation that another one starts, such as a helper's, takes that conversation's level, Auto at most.

Why A Web Page Can't Approve Its Own Action​

A page, email or file can hold text written to steer an AI ("ignore your instructions and send this file to…"). This is called prompt injection. Row-Bot's answer is to keep that text away from whatever decides.

Under Auto, the reviewer sees:

  • your own recent messages in the conversation: what you typed, never attachments (an unattended workflow uses its own saved steps instead);
  • the folder in play;
  • the action as its card describes it.

It never sees tool results, web pages, files, email, app output or Row-Bot's own notes. It approves only what clearly does what you asked, and asks you when an action goes beyond your request, reaches people you didn't name, posts publicly, moves money, grants access, or deletes something you didn't ask to change. It fails safe: an error, no answer within 30 seconds, an answer it can't read or no model available all mean it asks you. When it asks, the card says why. Actions it approved show Reviewer approved in the conversation's tool steps, with its reason.

Outside Text Is Fenced​

Results that carry someone else's words, such as web pages, search results, files, email, app and package results, and a helper's answer, reach the model inside a fence that marks them as outside content and tells it not to follow instructions found there. A scan for common injection tricks adds a warning to the fence when it finds one.

The fence and the scan are hints to the model, not a wall: a model can still be fooled. The wall is the approval gate, which the outside text never reaches.

Row-Bot's Own Data Folder Is Off Limits​

Row-Bot's data folder holds your conversations, memories, settings and keys, so its tools stay out of it:

  • the file tools refuse any path inside it, at every level, Hands-off included;
  • the Shell tool refuses a command that names it, in any common spelling or by a path relative to the current folder, and one that would run inside it;
  • in a sandbox Row-Bot, your real Row-Bot's data folder is out of reach too.

To let the agent read it, turn on Let the agent read Row-Bot's data folder in Settings › System › Advanced. Such commands then go through your approval level (Hands-off runs them, Block still refuses them). With the setting off, no level reaches the folder.

Programs On This Computer Can't Act As You​

On this computer, only Row-Bot's own window, or a browser it opens for you from its tray icon (Open in Browser), can change anything. Programs Row-Bot runs for you (a shell command, its own browser, a page it reads) connect from the same computer, so being on this computer isn't enough: they can look, never approve Row-Bot's own actions, change its approval level or settings, or pair a device. A Row-Bot tab you open yourself by typing its address shows View only on this computer in the sidebar until you open it from the window or the tray.

Your phone and every other device you signed in keep full access, and so does an account you paired in a chat app, for work that started there.

The Code Sandbox​

A code folder can run its commands in a Docker sandbox instead of on this computer (Code Folders). Changes reach your real folder only when you apply them.

The sandbox's network is off by default. When you turn it on, it reaches the public internet only: a small network gate beside it refuses this computer (so a local Ollama or Row-Bot itself), your local network and cloud metadata addresses. See The Sandbox Network.

Things Row-Bot Never Does​

  • Types a password, one-time code or card number. When a page or app asks for one, Row-Bot asks you to enter it.
  • Controls itself, a password manager or a protected system screen in computer use. Computer use's window pictures stay in memory and are never written to the chat, memory, logs or files.
  • Opens cloud metadata addresses or its own app in its browser.
  • Sends or changes something in the background. Proactive Row-Bot's background work only reads; anything that would send or change something goes through the same approval card as a chat.

What Is Not A Boundary​

The approval gate is the boundary. These are not, and the safer habit for each is beside it:

  • Hands-off runs everything. It still refuses blocked commands, tools you switched off and the data folder (unless you allowed it), but nothing else asks, and workflows don't pause. Use it for work you understand, in conversations you watch.
  • The reviewer is a model. It can approve an action that matches your words but not what you meant. Use Ask for unfamiliar or high-stakes work.
  • The workspace folder is open to the file tools. Inside it they read, write and copy without asking; moving and deleting ask. Choose a narrow workspace folder.
  • Commands, Row-Bot's browser and apps on your screen run as you. They have your account's rights on this computer; only a code folder's Docker sandbox isolates commands. Approvals decide what starts, not what a program does once it runs.
  • Packages and MCP servers that run on this computer aren't sandboxed. Their code can read files and start programs like any program. Their tools follow your approvals, but add them only from publishers you trust, and keep them off until you need them.
  • There is no list of allowed websites. A tool that may reach the internet can reach any public site. Addresses on this computer or your network ask first in Row-Bot's browser.
  • There is no single log of every action. Each conversation's tool steps record what ran and whether it was approved.
  • The fence and the injection scan are hints. See Outside Text Is Fenced.
  • A signed-in device is you. Anyone using your unlocked computer, or a phone you signed in, has full access. Sign out devices you don't use in Settings › Devices & remote access.
  • Your model provider sees what you send it. Prompts, attached files and tool results go to the provider of the model you chose. Use a model on this computer when that matters.

To try a workflow, skill or package before it touches real accounts, use a sandbox: a second Row-Bot on made-up data.

Reporting A Problem​

If you find a security problem, please report it privately, not in a public issue:

  • GitHub: Report a vulnerability on the repository's Security page opens a private advisory only the maintainer can see.
  • Email: syd@row-bot.ai.

Include the version, your system, the steps to reproduce and what an attacker gains. You'll hear back within 7 days. A confirmed problem with real impact gets a fix in a release and a published GitHub security advisory, with a CVE ID when its impact warrants one, and the reporter is credited unless they'd rather not be. Only the latest release is supported; a critical fix may be brought to an earlier one when practical. The repository's SECURITY.md has the same policy.

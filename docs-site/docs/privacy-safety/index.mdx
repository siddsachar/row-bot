# Privacy And Safety

Row-Bot is local-first: the app and its data live on your machine. Local-first does not mean every feature is offline. Hosted models, web search, browser actions, account tools, channels, MCP servers, plugins, realtime voice, and media providers can send data outside the app when you configure and use them.

## Local Data

Conversations, memories, documents, workflows, logs, designs, code folder records, skills, plugins, Buddy assets, and settings are stored in the active local Row-Bot data directory. Buddy's native overlay reuses the selected conversation and does not create a second transcript store.

Some things stay on this computer in particular ways:
- **Sign-ins in Row-Bot's browser**: its cookies are kept in the `browser_profile` folder of Row-Bot's data. **Settings › System › Browser and computer use** lists the sites, with **Sign out**.
- **Files Row-Bot sends to your devices**: kept for 7 days, then removed.
- **Pages**: a page runs with no internet and no access to your chats, files or tools.
- **Incognito chats**: nothing in them is read for memory. See [Incognito Chats](/docs/chat/#incognito-chats).

Row-Bot also records how many tokens each model call used, for the context ring and for questions such as "How many tokens did I use this week?". The record holds counts and timings only, never prompts, replies or files, and it stays on this computer; when you ask about usage, the counts go to the conversation's model like any tool result. Counts older than 90 days are removed, and deleting a conversation deletes its counts. See [Context And Usage](/docs/chat/#context-and-usage).

## External Calls

External calls happen when you choose or enable something that needs them: hosted models, subscription providers, API providers, web search, browser automation, account tools, messaging channels, MCP servers, plugin tools, realtime voice, and media generation. OpenRouter requests identify Row-Bot as the app making them (its website address and name, in the headers OpenRouter asks apps to send), which lets OpenRouter show Row-Bot in its public app rankings; these headers add no user, prompt or account data.

An installed Row-Bot also keeps itself up to date: about once a day it asks GitHub for a new release and, unless you turn background downloads off, downloads the changed files from GitHub and, when libraries changed, from the Python Package Index and PyTorch. Every file is checked against a published checksum, and update checks and downloads carry no account, usage or personal data. See [Updates](/docs/operations/updates#what-updates-contact).

Row-Bot also contacts these on its own, as Settings › System › Privacy lists: every hour it checks that it can reach the internet (Cloudflare's 1.1.1.1), Ollama and the accounts you connected, while **Check connections every hour** is on in Monitor; and model lists and the Apps & Skills catalogs update when you connect a provider, choose Refresh or Update, or turn on the catalog schedule (a model-list refresh also reads OpenRouter's public model list for context sizes).

### Every Connection At A Glance

| What | Where it goes | When | What it carries |
| --- | --- | --- | --- |
| The models you choose | That provider (OpenAI, Anthropic, Google, OpenRouter, Ollama on this computer, and others) | When a chat, workflow or background job uses the model | Your prompts, files you attach, and tool results for that request |
| Claude with your Claude plan | Anthropic, through your own Claude Code | When a chat uses a Claude plan model | The request. Row-Bot runs Claude Code with its telemetry, error reports and auto-updates turned off |
| Web search, reading pages, Row-Bot's browser | The search service and the sites involved | When Row-Bot looks something up or browses for you | The search words or the page request |
| Apps and accounts (GitHub, Google, Outlook through Microsoft Graph, X, MCP servers, plugins) | That service | When a tool of the app runs | What that action needs |
| Messaging channels | Telegram, Discord, Slack, WhatsApp or your SMS provider | When you or a workflow send through them | The message |
| Install stats | Row-Bot's stats service (Cloudflare) | About once a day | A random ID, the version and the system. See [Install Stats](#install-stats) |
| Updates | GitHub, and when libraries change, the Python Package Index and PyTorch | About once a day, and when downloading an update | Nothing personal. See [Updates](/docs/operations/updates#what-updates-contact) |
| Connection checks | Cloudflare's 1.1.1.1, Ollama and your connected accounts | Every hour, while **Check connections every hour** is on in Monitor | A simple reachability check |
| Catalogs | Your model providers, OpenRouter's public model list, the Apps & Skills catalogs | When you connect, refresh or update, or on the schedule you turn on | Nothing personal |
| ffmpeg, for video editing | The Python Package Index (`files.pythonhosted.org`) | Once, after you approve its card | Nothing personal; checked against its fingerprint |
| Cua Driver, for computer use | GitHub (the Cua project's releases) | When you choose Install or Repair | Nothing personal; then Cua Driver's own telemetry, described below |
| The browser runtime | Playwright's download servers | When you choose Install browser runtime | Nothing personal |

Computer use is a distinct opt-in boundary: Row-Bot works in an app with your real mouse and keyboard while a Stop bar shows on screen, and it asks before the first use of each app in a chat and before paying, sending, deleting or changing settings. Row-Bot downloads the pinned Cua Driver only after an explicit Install or Repair action, verifies the selected archive, and requires the current telemetry disclosure before any executable invocation. The reviewed 0.20.0 upstream telemetry includes pseudonymous identifiers and bounded product, platform, client, tool/outcome, duration/output, aggregate usage, permission, and lifecycle categories; its tagged event builders exclude prompts, tool arguments/results, typed text, screenshots, accessibility trees, app/window names, URLs, paths, raw values, and raw errors. See [Computer Use](/docs/computer-use/) for the full boundary.

## Install Stats

Row-Bot's only first-party telemetry is **install stats**: once a day it sends a random ID, its version and your system, nothing else, so Row-Bot's maker can see how many installations are in use (the installations reporting in the last 7 and 15 days) and which versions and systems to support. It is on by default, on desktops, servers and Docker alike, and Row-Bot doesn't ask about it; this page and the release notes describe it, and **Settings › System › Privacy** turns it off.

- **What is sent**: exactly `{"schema": 1, "install": "<random ID>", "version": "5.3.0", "os": "windows"}`. The ID is a random 128-bit number made just for this at the first send, never taken from your computer; `os` is `windows`, `macos`, `linux` or `docker`. Nothing else: no IP field, location, account, machine name, prompts, files, tools or models. It is a random ID, not your name, but it is the same ID every day, so it isn't anonymous.
- **When**: shortly after Row-Bot starts (a minute, plus up to an hour so installations don't all send at once), then at most once a day while Row-Bot runs, up to an hour late on purpose. A failed send waits for the next day. It never slows start-up.
- **Where**: over HTTPS from Row-Bot's server process to Row-Bot's stats service, a Cloudflare Worker at `row-bot-count.<account>.workers.dev`.
- **What is kept, and for how long**: the service keeps a keyed hash of the ID (it can't be turned back into the ID) with the day, the version and the system, and deletes it after 35 days. Daily totals of installations reporting in the last 7 and 15 days, by version and by system, and how many installations reported from each country each day, hold no IDs and are kept.
- **What anyone can see**: the service's current totals, the installations reporting in the last 7 and 15 days overall and by system, are public at `/v1/totals`. Nothing else is: not versions, countries, days or anything about one installation.
- **Your IP address**: Cloudflare sees it, as it does for any connection, and works out the country it comes from. Row-Bot's service doesn't store the address or anything else about the request: it only adds one to that country's count for the day, never next to the ID or the installation's records.
- **Turning it off**: switch off **Share install stats** in **Settings › System › Privacy**, or set `ROW_BOT_INSTALL_COUNT=0` (for example on a server or in Docker) before Row-Bot starts. Off stops at once, drops anything pending and stays off through restarts, updates, repairs and restores. On again uses the same ID and sends nothing for the days it was off.
- **Deleting what was sent**: **Delete what was sent…** under **Details** in Settings › System › Privacy turns install stats off and asks the service to delete every record of this installation. Row-Bot proves the request with a deletion secret kept on this computer; the service checks it against the ID and never stores it. Daily totals without IDs stay.

The ID and its deletion secret are kept in `install_count.json` in the Row-Bot data folder. They are never logged or shown, and backups never include them: a restore on this computer leaves them as they are, and a profile restored on another computer counts as a new installation.

## Credentials

Enter credentials only on the relevant Settings page or in the provider sign-in flow. Row-Bot stores secrets in the operating system key store when available and keeps local metadata for status and diagnostics. An explicitly configured server deployment can use a read-only external master-key file to encrypt owner-entered secrets in its persistent data directory; see [Docker And VPS Operations](/docs/operations/docker#read-only-secret-files).

If a hosting service runs Row-Bot for you, read [What Your Host Can See](/docs/privacy-safety/what-your-host-can-see).

## Remote Access

Remote Access is single-owner and multi-device. A Tailscale, LAN, SSH, Docker, or reverse-proxy route provides reachability only; each non-local browser still needs a one-time invitation and a revocable Row-Bot session.

Every authenticated interactive browser has full owner authority. Phone/tablet and computer choices select compact or desktop presentation only; device metadata and screen size are not permission boundaries. Row-Bot does not provide guest or multi-user sharing.

Invitation links expire after 10 minutes and work once, but should still be treated like passwords until they expire. Row-Bot stores only hashed invitation and session secrets. Session credentials use HttpOnly cookies and are not placed in URLs.

Prefer Tailscale or HTTPS for remote access. Plain LAN HTTP is unencrypted and does not support a remote browser microphone. For an operator-managed proxy, allow only the canonical browser-facing origin and trust only the exact address that connects from the proxy to Row-Bot. Never resolve a forwarding-header error by trusting every private address or a whole container network.

See [Remote Access And Server Mode](/docs/operations/remote-access) for layouts, lifetimes, revocation, Tailscale ownership, server mode, Docker, and recovery.

## Approvals

<Screenshot id="chat-approval" alt="Row-Bot approval card for a file change with Approve and Deny." caption="An approval card names the action and what it affects; Approve and Deny decide it in place." />

Use approvals to review file writes, command execution, browser actions, account actions, channel sends, MCP calls, plugin tools, code folder changes, and other sensitive actions. Deny anything that does not match your request.

Approvals wait until you answer; they no longer expire on their own, unless a workflow step sets its own time limit. Every waiting approval shows in its conversation, in the sidebar's attention indicator and on Overview, with **Approve** and **Deny** in place, so background work can't slip past you. Each tool result records whether approval was needed, given or denied, and a denied action never runs.

Approval level is policy: blocked actions stay blocked, **Ask** waits for you, **Auto**'s reviewer approves only what clearly matches your own request (it never sees tool results, files or web pages, and asks you when unsure), and **Hands-off** runs every action and records it. Some prompts include a short model-written reason for readability, but the underlying approval gate and action details are system-controlled.

### Programs On This Computer Can't Act As You

On this computer, only Row-Bot's own window, or a browser it opens for you from its tray icon (**Open in Browser**), can change anything. Programs Row-Bot runs for you (a shell command, its own browser, a page it reads) connect from the same computer, so being on this computer isn't enough: they can look, never approve Row-Bot's own actions, change its approval level or settings, or pair a device. A Row-Bot tab you open yourself by typing its address shows **View only on this computer** in the sidebar until you open it from the window or the tray. Your phone and every signed-in device keep full access.

## Sharing Logs Or Screenshots

Before sharing logs, screenshots, documents, thread exports, or review packages, check for names, file paths, account names, message contents, tokens, private documents, or misleading real data.

## Safer Defaults

- Start with local models when privacy matters most.
- Keep channels, MCP, and plugins disabled until needed.
- Keep Computer Use disabled until a local interactive task needs native application control.
- Keep Remote Access off until another trusted device needs it; use the narrowest route and the appropriate layout.
- Use narrow workspaces for file tools.
- Review approvals before external or destructive actions.
- Keep a final human review step before publishing screenshots or docs built from a personal app state.

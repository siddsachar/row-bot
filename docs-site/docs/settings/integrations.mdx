# Settings: Integrations

Open **Settings → Integrations** and choose **Apps & tools (MCP)**, **Skills**, or
**Plugins**. The choice is remembered on this device. Each category has
**Discover** and **Installed**. Old Skills, Plugins and MCP links still select the
appropriate category; **All types** is an advanced installed inventory view.

**Discover** has one **Search** action across enabled, eligible catalogs. Search
may send the query to public catalogs. Typing, opening the page, changing category,
going Back and filtering **Installed** do not start a public search. Official MCP
Registry results always search a dated local snapshot. Inspection can contact the
source to recheck the exact version and setup declarations before adding it.

Each result names its publisher and source. A listing, a compatible setup recipe,
authentication, and successful tool use are different evidence. Unknown
compatibility remains unknown. A service-name match is not proof that the service
vendor published it; alternatives retain separate identities. Full-width details
keep the review and next action together. Back restores the list and query.

Open **Catalogs** under advanced controls to see eligibility, saved age, snapshot
provenance and unavailable-source reasons. Catalog switches are preferences for
this browser/device, not account-wide settings or service permissions. They store
category and disabled catalog IDs, not queries or secrets. Disabling a catalog
does not remove an installed integration. Partial failures retain useful results;
retry is explicit. A bounded or stale snapshot is not an exhaustive current catalog.

## Three ways to add capability

- **Apps & tools (MCP):** inspect the destination and hosted/local requirements,
  add the connection, then complete only its required setup. Declared no-auth
  connections omit account fields. OAuth opens the supported sign-in flow; API
  keys use protected connection-specific bindings. Unknown auth requires further
  configuration. Review runtime preparation before executing local code, test the
  connection, accept its tested tools, then turn it on and connect. Saving a token
  is not successful authentication or tool use.
- **Skills:** inspect the complete reviewed instructions, supporting files,
  scripts, scanner findings, version and requirements. Add the skill, then choose
  availability and pinning. A skill supplies instructions; it does not establish
  an external account connection. Binary or unavailable file content is disclosed.
  Built-in skills and added skills are labeled separately.
- **Plugins:** inspect the package format, included capabilities, permissions,
  files and prerequisites before installing. Finish required child setup from the
  checklist. A healthy package process cannot hide a required missing or failed
  child. Optional children must be explicitly declared. Included skills and MCP
  connections remain owned by their package; manage updates/removal at the parent.

**Add from link or file** is a secondary path for supported public skill/package
links, authorized local packages and custom MCP configuration. Inspection does not
execute downloaded code. New public additions start off. **Advanced configuration**
keeps skill creation/editing/proposals, custom launch settings, JSON import, native
plugin settings and the existing MCP controls available.

## Accounts, access and first use

Use separate connections and account labels such as Work and Personal for separate
accounts. Credentials belong to a connection, not the general Accounts page.
Sign-in does not enable tools. Required scopes, subscriptions and costs come from
publisher information; missing information is shown as unknown.

Tested tools are grouped by read, change and high-impact effects. Unknown effects
remain conservative. Review the complete catalog and per-tool controls. Local tool
permissions do not revoke grants at the upstream service. Existing approvals,
Agent Profiles and model/runtime restrictions still apply. The standalone global
MCP switch can expose other already-enabled standalone connections; its review
explains that effect. Package-owned children also require their parent to be on.

**Try in chat** checks the selected chat's current profile, model and integration
eligibility, then prepares a visible draft. It preserves existing text and
attachments and does not change the profile or model. It neither sends the draft
nor calls a provider or service tool. Review it and choose Send yourself.

OAuth uses PKCE, expiring one-use state, protected credentials and endpoint binding.
Desktop callbacks use the actual loopback address and port. Browser/server access
requires one approved HTTPS callback origin; arbitrary Host headers cannot supply
it. Cancel interrupted/expired sign-in before restarting. Services requiring a
registered OAuth client may need additional supported configuration; generic OAuth
support is not a claim that every provider accepts Row-Bot.

API keys are bound to explicit headers or process environment variables and are
not displayed after saving. Plaintext fallback is refused. Managed npm preparation
accepts only integrity-pinned self-contained releases or complete shrinkwraps
without install scripts. Arbitrary bootstrap and unpinned dependencies remain
outside automatic setup. Processes are not OS-sandboxed: review file, network and
telemetry behavior before execution. Shared Node/uv runtimes survive package removal.

## Updates, recovery, off and removal

Updates stage reviewed files before replacing the active version. The review names
file, tool, permission, destination and declared dependency changes. Rejection or
failed staging preserves the prior usable revision. Local skill edits are preserved;
duplicate or export them before updating. Managed file updates retain one previous
revision. Restore cannot undo data migrations, external writes or a hosted service's
changes. Changed hosted tools require a fresh test and catalog acceptance before
new or changed tools become available.

After an uncertain action, use the retained **Check original operation** control.
It checks the same receipt; it does not replay the action. Conflicting actions stay
blocked until the existing owner confirms a terminal or reconciled result. Recovery
can finish a proven publication or retry incomplete bound credential cleanup.
Uncertain outcomes remain explicit, including after reload.

**Turn off** preserves configuration, permissions, data and credentials. Turning a
package off withdraws its children; already-running work may need separate stopping.
**Disconnect account** clears only the selected connection's local credential
binding and stops its transport. It does not claim verified remote revocation;
use the service's account controls when needed. Incomplete cleanup remains visible.

Removal previews owned children. Package saved data is retained by default, with
separate reviewed **Delete saved data** cleanup. Standalone MCP removal also retains
protected credentials by default; explicitly select bound credential cleanup if
wanted. Unrelated connections, packages and shared runtimes remain outside removal.

## Catalog access and compatibility

Default vendor recommendations include Notion and Linear. Developer examples
(Local text tools and Hello Tool) are explicit imports, not default service results.
ClawHub skills retain complete pinned files and moderation checks. Hermes is an
ordinary source of pinned packages and bounded MCP recipes. Portable Agent Plugins
1.0 supports the implemented declarative skills/MCP subset; native Row-Bot v2 uses
its existing owner. Native Hermes/OpenClaw SDKs, hooks and foreign entry points are
not made compatible by a catalog listing.

As reviewed on **3 October 2026**, optional catalogs have these access limits:

- [skills.sh](https://www.skills.sh/docs/api): documented v1 access requires Vercel
  OIDC. An anonymous legacy response does not establish a desktop access contract.
- [Glama](https://glama.ai/mcp/reference): directory reads require a key and data
  license compliance, visible Glama credit and a backlink for every displayed
  listing. This integration is unavailable; no telemetry endpoint is used.
- [PulseMCP](https://www.pulsemcp.com/api/docs/v0.1): private B2B access needs a tenant
  ID and API key; no approved desktop integration is configured.
- [Smithery](https://smithery.ai/docs/api-reference/servers/list-all-servers): its
  documented bearer requirement conflicts with an anonymous 200 probe on 3 October.
  Desktop catalog access remains unresolved.
- browse.sh and LobeHub: a suitable public skill discovery contract is unproven.
  Explicit supported imports remain separate from catalog eligibility.
- [ClawHub plugins](https://docs.openclaw.ai/clawhub/http-api): a bundle label does
  not prove compatible package contents. Plugin-family discovery remains deferred.

There are no guessed-endpoint or HTML-scraping production fallbacks. The bundled
Registry snapshot is local metadata; a maintained production refresh/feed and
redistribution arrangement remains unresolved. No background central crawl or new
Row-Bot cloud catalog was introduced. Registry metadata licensing does not license
its referenced packages.

## Verification limits

Deterministic tests use isolated files, fake catalogs/transports and protected
storage fakes. Real catalog metadata and inspected packages do not prove live use.
Disposable account OAuth, approved reads/tool use, refresh/disconnect and real
Work/Personal isolation remain pending; real writes need separate authorization.
Windows native OAuth, macOS/Linux host checks and participant usability testing
remain pending. Installer/signing/notarization and release validation are outside
this work. Catalog sizes are not counts of working Row-Bot integrations.

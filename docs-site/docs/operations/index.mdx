# Operations, Data, And Recovery

Row-Bot is local-first, so operational safety starts with knowing which data directory and workspace are active. Conversations, settings, memory, Knowledge, workflows, documents, designs, code folder records, skills, plugins, logs, channel state, and MCP configuration can live under that directory. Operating-system key stores may hold credentials separately.

## Remote Access And Server Operations

Use [Remote Access And Server Mode](/docs/operations/remote-access) for the complete guide to one-time invitations, desktop and compact owner sessions, Tailscale Serve, LAN, SSH forwarding, Docker, HTTPS reverse proxies, browser-local voice, access recovery, and proxy error diagnostics.

Use [Docker And VPS Operations](/docs/operations/docker) for pull-first Compose startup, release and digest pins, persistent volumes, offline backup and restore, explicit upgrade and rollback, host Caddy or Tailscale, secret-file mounts, and container-specific Developer boundaries.

Use [Hosting Row-Bot](/docs/operations/hosting) to run the image as one container, the way a hosting service does: its settings, the secret-store key, sizes and updates.

Remote access remains off by default in ordinary desktop launches. Server operators should back up access state with the rest of the active data directory, keep one worker, publish one canonical origin, terminate remote traffic with HTTPS, and trust only the exact reverse proxy that connects to Row-Bot.

## Back Up

**Settings › Data › Back up and restore** makes a copy of your Row-Bot on this computer, without passwords or sign-ins. Choose **Back up now**; the command palette finds it as "back up". Files a reply was still uploading are left out, and a file that can't be read is named in the result ("Left out a file that couldn't be read: …") instead of stopping the backup.

The backup is saved in the workspace's Backups folder. In the desktop app on the computer Row-Bot runs on, **Show in folder** opens it there. On any other device, such as a phone, another computer's browser, or a server or Docker install, **Download** saves the last backup on that device.

To copy everything by hand instead:

1. Stop running workflows, channels, servers, and active replies.
2. Close Row-Bot so databases are not changing during the copy.
3. Copy the whole active data directory to protected storage.
4. Back up code folders, exported design files, and wiki vaults separately when they live elsewhere.
5. Record the Row-Bot version used with the backup.

## Restore

**Restore from backup** on the same page restores a backup made there. In the desktop app you pick the file; on any other device you choose it in the browser, and it's sent to Row-Bot first (**Stop** cancels the transfer). Row-Bot checks the file, refuses one that isn't a Row-Bot backup, comes from a newer Row-Bot, or is damaged, and lists what to set up again afterwards, such as passwords and sign-ins. Nothing changes until you choose **Restore on restart**: the restore applies the next time Row-Bot starts, with your current profile kept aside in a `before-restore-<time>` folder. A sent file you don't restore is deleted.

To restore a hand-made copy, restore related databases and files as one set while Row-Bot is closed. Point a test launch at the restored directory first, then check conversations, providers, workflows, Knowledge, documents, designs, code folders, plugins, MCP, and channels. Reconnect secrets that were stored in an OS keychain and were not included in the backup.

## Import From Another Assistant

**Settings › Data › Import from another assistant** scans Hermes Agent or OpenClaw data on this computer and lets you choose what to bring in: memories, persona and skills, and, only if you tick it, API keys and tokens. Nothing is written until you confirm the preview. First launch offers it when it finds one of them. The same page's danger zone holds irreversible clean-up, such as removing tracker data.

## Sandboxes

**Settings › Data › Sandboxes** makes a second Row-Bot on made-up data, for trying a workflow or skill before it touches real accounts, filming a demo, or showing Row-Bot to someone without your data. Name it, choose what it starts with (a small shop with its own web app, a charity's documents, household paperwork, sample code, or nothing), and choose **New sandbox**. Ask Row-Bot in a chat and it can make, start and open one too; starting one asks first, by the approval level. It reuses a signed-in sandbox with the same data rather than making another, unless you ask for a new one.

- **Start** runs it on this computer only, with its own chats, settings, memory, workspace and sign-ins. A hosted model needs its own sign-in there, once; local models work at once, and a sandbox Row-Bot makes from a chat on a model on this computer starts with that model chosen. Chats in a sandbox Row-Bot made start at the approval level of the chat that made it (Hands-off becomes Auto), so a demo isn't left waiting on an approval in a window you can't see; change it there like any chat's.
- **Open** signs your browser in to it with a one-time link. Row-Bot's own browser can open it the same way, to film a demo. There, Row-Bot sends without asking (to the sandbox's chat, or a made-up customer), as it reaches no one; paying, deleting, account changes and uploads in a sandbox still ask.
- **Its mark**: every window of a sandbox says **Sandbox · made-up data** in the sidebar.
- **What it can't do**: see your own Row-Bot, its data folder or your keys and tokens; update Row-Bot; count installs; or start sandboxes of its own.
- **Reset** takes it back to what it started with, keeping its model sign-in, **Stop** ends it, and **Delete** removes it. Every sandbox stops when Row-Bot quits. At most five.

## Update, Repair, And Uninstall

Row-Bot downloads updates in the background and installs them when it restarts; **Settings › Updates** shows the version you have, the update **Channel**, what is downloading or ready, and **Restart now**. **Repair** there goes back to the version you had before. [Updates](/docs/operations/updates) explains each step, how to turn background downloads off, and what updates contact.

Back up before a major update: Repair goes back to earlier application files but is not a data backup. Uninstalling the application and deleting the data folder are separate decisions; [Installation](/docs/getting-started/installation#uninstall) lists both locations for each system.

## Logs And Support

Use Monitor and the local log folder to diagnose startup, provider, workflow, channel, and background failures. Before sharing diagnostics, remove names, paths, account identifiers, document content, prompts, message content, tokens, and screenshots that expose private data.

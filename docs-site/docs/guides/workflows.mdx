# Workflows

Workflows are repeatable Row-Bot tasks. Use them for things you want to run again: a morning brief, inbox follow-up, document digest, research check, report draft, or channel delivery. A **reminder** is a simpler kind that just tells you something at a chosen time.

A workflow is a chat that runs on its own: each run sends your message to the workflow's own conversation, in the background, and Row-Bot works on it exactly as it would in a chat. It has every tool a chat has, finds apps and tools the same way, and asks before actions at the same approval level, on the same cards.

For the execution model behind schedules, persistent runs, approvals, and delivery, read [How Background Workflows Run](/docs/concepts/background-workflows).

## Where To Find Workflows

Choose **Home**, then the **Workflows** tab. Overview's **New workflow** quick start and the ⌘K command palette (**Run …**) also reach them.

## The Workflow List

- Each row shows the workflow's name, when it runs next, its last runs, and small tags for its profile and approvals. **Hands-off** stands out.
- **Run** starts the workflow at once, in one click. The row then shows its live state and **Stop**.
- **Enable** or **Disable** turns the workflow's schedule on or off.
- **Edit** opens the workflow editor.
- The row's **⋯** menu opens **Run history**, **Workflow settings** or the workflow's conversation (**Open conversation**), and can duplicate or delete the workflow.
- **Search workflows**, the filter and **Select workflows** help with long lists.
- **Delivery defaults** choose the external channels every workflow also sends results to, unless a workflow chooses its own. The app always shows the result.

## Create A Workflow

1. Choose **New workflow**. The editor opens on the page, as editing does.
2. Give it a name, an icon and a short description, and choose **Workflow** or **Reminder**.
3. Write the **Messages**: what you would type in a chat. One message is enough for most workflows; **Add message** sends another after the first is done, in the same conversation, so it can build on the answer. Say what to do when there is nothing to do. Type `{{` to add the date. Drag messages, or use the arrow keys, to reorder them.
   - Keep a message short and positive: what to make, for whom, in what voice, and where the results go. For example: "Each weekday, write one post for @rowbot_ai about something Row-Bot does well, for people who run AI on their own computer. Friendly and concrete. Post it."
   - Leave out the rules Row-Bot already keeps: the approval card for each post or email, the account it names, the length limit, and never sending the same thing twice.
4. Choose **When it runs**: manually, at a date and time, or repeating. Repeating can be every day, weekdays, chosen days, **Monthly**, every few hours or minutes, or a custom cron expression. **Timezone** starts at the timezone of the device you're using, and you can search for another. A daily time stays the same across daylight saving.
5. Choose **Send results to**: follow your defaults, choose channels only for this workflow, or keep results in the app.
6. Under **Change model and approvals**, pick an **Agent profile** and **Approvals**:
   - **Ask before actions**;
   - **Auto, reviewed**: a reviewer approves what matches the workflow's own messages;
   - **Hands-off**: nothing pauses;
   - **Block actions**.
7. Save, then **Run** it once and review the result.

## Its Conversation

- Every run of a workflow is a new turn in the same conversation, marked with when and how it started, such as **Scheduled run · 26 Oct, 08:00**. Open it with **Open conversation** to read what each run did, see its approval cards, or carry on in it yourself.
- A run's outcome comes from what its tools did, never from the model's own words: **Posted**, with the post's link, for example, or **Not sure it went through** when a tool couldn't confirm it. A run you said no to ends **You said no to …**, naming what you refused, and its notes keep a dated line so the next run knows and doesn't try it another way.
- A run that fails on a passing problem, such as the network or a busy provider, tries again by itself after a wait. Once something has gone out, it never tries again: nothing is posted or sent twice.
- A workflow keeps short notes between runs: what it checked and when, ids it needs again, what's left. Each run reads them first and updates them before it ends, so it doesn't check again what an earlier run already did. Updating them shows as a step in the run.
- A run has the tools and skills a chat has, including skills you made in other chats.
- Workflows hand work on by sending it, by the other workflow's name: a trends workflow ends by sending its brief to the publisher workflow's conversation, which starts a turn there. An update that needs no answer is sent without asking for a reply, and a note can wait for the other workflow's next run instead of starting a turn now.
- A post made for a time slot waits in **Home › Review**, where you edit it, approve it or say no; approved, it goes out at its time.
- A run can wait for something and carry on when it happens: a build or check to pass, a page to change, a time, or another workflow to finish. Nothing runs while it waits. **Home › Waiting** and the conversation show what it waits for, with **Stop**. Pictures, clips and voice lines pass through **Library › Media**, where a workflow finds, tags and copies them. For real screenshots and clips, a workflow uses a [sandbox](/docs/operations/#sandboxes), never your own Row-Bot.
- A run has no step limit to set. It keeps going while it makes progress, and stops when you press **Stop** or when it keeps repeating the same thing. After a very long run of steps it stops and asks **Keep going?**: send **Continue** in its conversation to pick up from there.

## Workflow Settings

- **Workflow settings** chooses the model and the trigger: manual and scheduled runs only, **When another workflow completes**, or **Webhook (HTTP POST)**. A webhook trigger creates a private secret when you save; download its configuration and keep it private.
- **If Row-Bot is closed at a scheduled time**, in Workflow settings:
  - **Skip it** (the default);
  - **Run once when Row-Bot starts**: only the latest missed time runs, and the run says it ran late.
- **Send results**, in Workflow settings, chooses when results reach the workflow's channels. Each one starts with what happened: **Sent** and what went out, **Finished · nothing was posted or sent**, **Not sure it went through**, or **Didn't finish**.
  - **After every run** (the default);
  - **Only when it needs me**: a run that didn't finish, or isn't sure something went through. Approvals still reach you;
  - **In a daily digest**: one message from 6 PM, with a line for each run that day.
- **Code folder**, in Workflow settings, gives the workflow a [code folder](/docs/developer/) of its own: its conversation works in it. **None: the conversation's folder** keeps today's behaviour. If the folder is removed, the next run stops, says why, and opens the settings at **Code folder** so you can choose another.
- **Always ask me**, in Workflow settings, makes actions in the apps you tick wait for your own approval on every run, even on Auto or Hands-off, for up to 16 apps. The card shows exactly what will happen.

## Workflows With Apps

- **Start from a template**, below the workflow list, offers workflows that use apps: **GitHub pull-request digest**, **Linear triage** and **Notion weekly summary**. Each is created switched off, with a schedule and **Ask before actions** approvals; turn it on when it suits you. A template whose app isn't connected shows **Connect** instead. Templates never add a webhook or change how Row-Bot can be reached.
- A workflow uses apps as a chat does. Mention an app in a message, such as `@notion`, to keep that message to it; otherwise Row-Bot finds what it needs. **Delivery** lists only the channels you have set up.
- On **Auto**, a reviewer approves what matches the workflow's own messages; anything else, including an app action its access asks about that the reviewer isn't sure of, pauses the run and waits for you. On **Hands-off**, which you turn on in the workflow's settings, nothing pauses for approval.

## Approvals In Workflows

An action that needs approval pauses the run on the same card a chat shows, with everything it will do: a post's full text and account, or an email's recipients and body. It waits until you answer. Answer it in the workflow's conversation, or from the sidebar's attention indicator or Overview's **Needs you**, whose **Review** opens the card. A run still waiting when the next one starts is replaced: its card is withdrawn, so a day-old post can't go out, and the run ends **Expired**, saying a newer run replaced it.

## What Is Saved

Workflow definitions, schedules, run history, delivery defaults, and status are local Row-Bot data. Results may be sent to channels only when configured and selected.

## Safety

Avoid workflows that send messages, write files, start servers, or call external systems without a review point. Use approvals for actions that can affect files, accounts, channels, MCP servers, plugins, or external services. Remember that **Run** starts at once, including any delivery outside the app.

## Troubleshooting

- If a workflow does not run on schedule, check that it is enabled. A run that starts while the one before is still working is skipped and says so. A run missed while Row-Bot was closed is skipped unless the workflow's settings say **Run once when Row-Bot starts**.
- If a run stopped with "Choose a folder", its code folder was removed: choose another in its settings, or **None**.
- If delivery fails, check the selected channel and its Settings page.
- If a run waits for approval, answer it from the attention indicator or Overview.
- If a run stopped and asked **Keep going?**, send **Continue** in its conversation.
- If results are too broad, make the message narrower, or add a second message that works on the first answer.
